# ElectroSim Pro ⚡

محاكي كهرباء احترافي وتفاعلي لأندرويد (Flutter) يجمع بين:
**كهرباء البناء + الكهرباء الصناعية + الإلكترونيات الأساسية + منصة تعلّم** في تطبيق واحد قابل للتوسع.

> ⚠️ **تنبيه سلامة**: هذا تطبيق **تعليمي/محاكاة فقط**. أي عمل كهربائي حقيقي (خصوصاً 230V/400V)
> يجب أن ينفّذه فني كهرباء مؤهّل ومرخّص، باتباع معايير السلامة المحلية.

---

## 1) لمحة سريعة

- **المنصة الآن:** Android (عبر Flutter)، مع بنية جاهزة للتوسّع لاحقاً إلى iOS والويب بنفس الكود.
- **محرك المحاكاة حقيقي فعلياً**، وليس رسماً متحركاً ثابتاً: يبني الدائرة كرسم بياني (Graph)،
  يحلّها عددياً بطريقة **Modified Nodal Analysis (MNA)** في كل "نبضة" (tick) كل 100ms، ثم يحدّث
  حالة كل مكون (إضاءة، دوران، فصل قاطع، تفعيل ريليه...) بناءً على النتيجة الفعلية.
- **مكتبة مكونات كبيرة (Data-Driven)**: إضافة مكون جديد = سطر جديد في `lib/data/component_catalog.dart`
  دون الحاجة لتعديل محرك المحاكاة أو الواجهة.
- **وضعان للعرض**: واقعي (Realistic) ورمزي (Electrical Symbol)، قابلان للتبديل بزر واحد.
- **بدون تبعيات إدارة حالة خارجية**: فقط `ChangeNotifier` + `ListenableBuilder`/`AnimatedBuilder`
  من Flutter SDK القياسي (قرار مقصود لتقليل المخاطر والتبعيات).

## 2) البنية المعمارية (Architecture)

```
app/
├─ lib/
│  ├─ models/        # نماذج البيانات الخام (تعريف مكون/نسخة مكون/سلك/مشروع/تعدادات)
│  ├─ data/          # مكتبة المكونات (component_catalog.dart) — قلب قابلية التوسّع
│  ├─ engine/        # محرك المحاكاة: بناء الرسم البياني + حلّ MNA + منطق كل سلوك + كشف الأعطال
│  ├─ state/         # ProjectController / SimulationController / AppSettings / ProjectsRepository
│  ├─ core/          # الهوية البصرية (Theme) الداكنة الاحترافية
│  └─ ui/
│     ├─ widgets/    # لوحة الرسم التفاعلية، رسّام المكونات، مكتبة المكونات، شريط الأدوات...
│     └─ screens/    # الشاشات: الرئيسية، المحرر، التعلّم، محاكاة الأعطال، الإعدادات
├─ assets/icon/      # أيقونة التطبيق (تُستخدم بواسطة flutter_launcher_icons)
└─ pubspec.yaml
```

### تدفّق البيانات

```
ComponentDefinition (قالب ثابت في component_catalog.dart)
        │  addComponent()
        ▼
ComponentInstance (نسخة موضوعة على اللوحة داخل ProjectModel)
        │
        ▼
CircuitGraph (يُبنى من كل تكرار محاكاة: عُقَد + حواف مقاومة/تيار)
        │  MnaSolver.solve()
        ▼
MnaResult (جهد كل عقدة) ─▶ SimulationEngine يحدّث runtimeState لكل مكون
        │
        ▼
DetectedFault[] + wireCurrents + totalPowerW ─▶ الواجهة (FaultBanner, ComponentPainter, ...)
```

### لماذا هذا التصميم قابل للتوسّع؟

- إضافة **مكون كهربائي جديد بالكامل** (مثلاً "قاطع DC" أو "حساس حرارة صناعي") تحتاج فقط:
  1. سطر `ComponentDefinition` جديد في `component_catalog.dart` (الأطراف، الفئة، الخصائص الافتراضية).
  2. حالة `case` جديدة في `SimulationEngine` إن كان له سلوك كهربائي مختلف عن الموجود (أو إعادة استخدام سلوك حالي).
  3. (اختياري) رسم مخصص في `ComponentPainter` — وإلا سيُستخدم رسم عام تلقائياً.
- لا حاجة لتعديل `ProjectController`, `CircuitCanvas`, `ProjectModel` أو أي شاشة عند إضافة مكونات جديدة.

## 3) محرك المحاكاة (Simulation Engine)

- `CircuitGraph`: يحوّل كل نسخة مكون + كل سلك إلى عُقَد وحواف (مقاومة/تيار) قابلة للحل.
- `MnaSolver`: يحل مصفوفة المعادلات الخطية (Modified Nodal Analysis) للحصول على جهد كل عقدة.
- `SimulationEngine`:
  - يحدّث حالة كل سلوك (`BehaviorKind`) — مفاتيح، قواطع، كونتاكتورات، محركات، RCD، مصادر AC/DC...
  - يحسب: Voltage / Current / Resistance / Power / Energy / Frequency لكل مكون حسب الحاجة.
  - **الحماية الفعلية**: قاطع MCB/Disjoncteur يفصل تلقائياً عند تجاوز 6× التيار المقنن (قصر) أو
    تجاوز التيار المقنن لفترة زمنية معكوسة تناسبياً (Overload، مطابق لمبدأ Inverse-Time Tripping).
  - **RCD حقيقي**: يقارن التيار الداخل (Phase) بالخارج (Neutral) ويفصل عند تجاوز حساسية التسرب.
  - **محرك ثلاثي الطور**: يفصل التنبيه عند فقدان أحد الأطوار (Phase Missing)، ويعكس اتجاه
    الدوران (المحاكى بصرياً) عند عكس ترتيب طورين.
  - `_detectFaults()`: يفحص كل مكون بعد كل نبضة ويولّد `DetectedFault` بعنوان + شرح + حل مقترح
    بالعربية، مرتبط مباشرة بالمكون المسبب لتلوينه/الإشارة إليه في الواجهة.
- ثوابت فيزيائية مبسّطة (موثقة داخل الكود): `kClosedConductance = 2000.0` (موصلية تقريبية لسلك/تلامس
  مغلق مثالي)، `kOpenConductance = 1e-9` (تسرّب شبه معدوم لتلامس مفتوح)، تُستخدم لتفادي عدم استقرار
  الحل العددي مع الحفاظ على دقة عملية كافية للأغراض التعليمية.

## 4) الميزات المُنفَّذة فعلياً

- مكتبة مكونات واسعة: مصادر طاقة (DC/AC أحادي/ثلاثي الطور، 12/24/48/110/220/230/380/400V)،
  إنارة (مصباح عادي/LED، جرس)، مفاتيح (أحادي/مزدوج/متعدد/تبادلي/درج)، مقابس، علب توصيل، لوحة توزيع،
  حماية (قاطع رئيسي/MCB/قاطع محرك/فيوز/RCD)، تحكم (كونتاكتور + تلامس مساعد NO/NC، ريليه + تلامس،
  ريليه حراري، تايمر، عداد، ثرموستات، PLC مبسّط)، أزرار وحساسات (NO/NC/توقف طارئ/سيلكتور/ليميت
  سويتش/حساس رقمي)، محركات (DC صغير، مروحة، أحادي/ثلاثي الطور)، صناعية (محول، Star/Delta، DOL)،
  أجهزة قياس (مالتيميتر، فولت/أمبير/أوم ميتر، كلامب ميتر، واطميتر، تردد، عداد طاقة، أوسيلوسكوب)،
  إلكترونيات أساسية (مقاومة، مكثف، دايود، LED، ترانزستور، بوتنشيومتر، بازر، IC مبسّط).
- Canvas تفاعلي: Zoom/Pan (`InteractiveViewer`) + شبكة خلفية + تحديد/سحب مكونات + تدوير 90° +
  حذف + تكرار (Duplicate) + نسخ/لصق (Copy/Paste) + قفل مكون + Undo/Redo (حتى 60 خطوة).
  توصيل الأسلاك حالياً بنمط **نقر-نقر (tap-to-connect)**: اضغط على طرف ثم على الطرف الآخر
  (مبسَّط عمداً بدل سحب مباشر لضمان دقة اللمس على الهاتف؛ سحب-وإفلات فعلي للأسلاك ضمن خارطة الطريق).
- ألوان أسلاك تلقائية حسب النوع (Phase/Neutral/Ground/DC+/DC-/Control) **قابلة للتخصيص من الإعدادات**،
  مع تحذير فوري عند محاولة توصيل غير متوافق (مثال: Phase مباشرة مع Neutral).
- تشغيل/إيقاف مؤقت/إيقاف/إعادة ضبط المحاكاة مع مؤثرات بصرية حقيقية مرتبطة بالحساب الفعلي:
  توهّج المصباح يتناسب مع القدرة الفعلية، نقاط تدفّق متحركة على الأسلاك تتحرك حسب التيار الفعلي،
  دوران المروحة/المحرك يتسارع مع نسبة الحمل، فصل القاطع يُطفئ الدائرة فوراً.
- تفاعل مباشر أثناء التشغيل: النقر على مفتاح/زر/سيلكتور يبدّل حالته فعلياً ضمن الحساب (وليس مجرد
  تأثير بصري)، والضغط المطوّل على أي مكون يفتح لوحة خصائصه (إعادة تسمية، تعديل قيم رقمية، ربط
  تلامس مساعد بملف الكونتاكتور/الريليه المطلوب).
- نظام اكتشاف أعطال تلقائي أثناء التشغيل (قصر دائرة، تحميل زائد، احتراق فيوز، تسرّب أرضي RCD،
  خطأ توصيل محرك ثلاثي الطور) يظهر كشريط تنبيه بالعربية بعنوان + شرح + حل مقترح.
- وضع **"اكتشف العطل" (Fault Simulation)**: يبني لوحة كاملة **مصدر → قاطع رئيسي → RCD → MCB →
  كونتاكتور → ريليه حراري → محرك**، يحقن فيها عطلاً عشوائياً واحداً (قصر دائرة / تحميل زائد /
  قطع توصيل)، ويطلب من المستخدم اكتشافه وإصلاحه، مع زر تلميح اختياري ومكافأة XP عند الإنجاز.
- قسم **التعلّم (Learning)**: 4 دروس تدريجية (مصباح ومفتاح ← مصباحان ومفتاحان ← تشغيل/إيقاف محرك
  بالكونتاكتور ← Star/Delta) + نظام XP/مستوى/شارات محفوظ محلياً، بالإضافة لدخول مباشر لتحدي اكتشاف
  الأعطال من نفس الشاشة.
- أدوات قياس كمكونات فعلية يمكن سحبها للوحة من تبويب "القياس" في الشريط السفلي.
- إدارة مشاريع كاملة: إنشاء/فتح/حفظ تلقائي كل 20 ثانية/حفظ يدوي/إعادة تسمية/نسخ/حذف/استيراد
  ملف/تصدير+مشاركة ملف (`.esp.json`) عبر `share_plus`.
- إعدادات: تخصيص ألوان الأسلاك حسب النوع، عرض/إعادة ضبط تقدّم التعلّم، تنبيه سلامة إلزامي يظهر
  مرة واحدة عند أول فتح للتطبيق.
- تصميم داكن احترافي ثابت (Dark Mode افتراضي ودائم) بهوية بصرية موحدة (`core/theme.dart`).

## 5) ما لم يُنفَّذ بعد (خارطة طريق صريحة)

هذه الجولة سلّمت أساساً احترافياً حقيقي الوظائف؛ النقاط التالية موثّقة عمداً كخطوات تالية:

- **سحب-وإفلات فعلي للأسلاك** (حالياً نقر-نقر) — تحسين تجربة المستخدم لاحقاً.
- **محاذاة (Align) وتجميع (Group) متعدد للمكونات** في وضع "أدوات" — البنية التحتية (تحديد متعدد)
  جاهزة جزئياً عبر `selectedComponentIds` لكنها غير مكتملة الواجهة.
- **منطق PLC كامل (Ladder Logic)** — حالياً `plcPlaceholder` عنصر نائب في المكتبة فقط.
- **Oscilloscope بموجة دقيقة حقيقية** — حالياً مؤشر قراءة رقمية مبسّط.
- **حقن أعطال إضافية تلقائية** (انعكاس قطبية DC، تلامس عالق NO/NC، Phase Missing على لوحات صناعية
  متعددة الأطوار) — البنية (`FaultType` enum) تدعمها، التنفيذ الكامل في وضع Fault Simulation مؤجَّل.
- **تصدير صورة/PDF للمخطط الكهربائي** — التصدير الحالي يقتصر على ملف مشروع `.esp.json`.
- دعم iOS/الويب الفعلي (البنية جاهزة عبر Flutter، لكن لم يُضَف/يُختبر أي إعداد منصة إضافي بعد).

## 6) بناء APK

**تعذّر تثبيت Flutter SDK/Android SDK محلياً في بيئة التطوير المستخدمة لكتابة هذا الكود** (حجب شبكي
لكل من `dl.google.com`, `pub.dev`, `storage.googleapis.com`... إلخ)، لذلك **كل بناء وتحليل فعلي
يتم حصراً عبر GitHub Actions**، حيث الشبكة غير مقيّدة.

### للحصول على APK جاهز

1. شغّل ورك‌فلو **"بناء APK لتطبيق ElectroSim Pro"** من تبويب Actions في GitHub (تشغيل يدوي
   `workflow_dispatch`)، أو ادفع أي تعديل داخل مجلد `app/` — سيُشغَّل تلقائياً.
2. بعد نجاح التشغيل: سيُحدَّث الملف [`dist/ElectroSimPro.apk`](../dist/ElectroSimPro.apk) داخل هذا
   الفرع نفسه تلقائياً (يكفي `git pull`)، بالإضافة لرفعه أيضاً كـ Artifact قابل للتنزيل مباشرة من
   صفحة التشغيل في Actions.
3. انسخ `ElectroSimPro.apk` إلى هاتف أندرويد وثبّته (فعّل "السماح بالتثبيت من مصادر غير معروفة"
   إن طُلب ذلك).

### للبناء يدوياً على جهازك (إن توفّر لديك Flutter SDK)

```bash
cd app
flutter create --platforms=android --org com.electrosimpro --project-name electrosim_pro .
flutter pub get
dart run flutter_launcher_icons
flutter build apk --release
# الناتج: app/build/app/outputs/flutter-apk/app-release.apk
```

## 7) التقنيات المستخدمة

| الطبقة | التقنية | السبب |
|---|---|---|
| اللغة/الإطار | Flutter (Dart) | كود واحد لأندرويد الآن، وقابلية توسّع حقيقية لاحقاً لـ iOS/الويب |
| إدارة الحالة | `ChangeNotifier` + `ListenableBuilder` (SDK قياسي) | تقليل التبعيات الخارجية والمخاطر |
| محرك المحاكاة | خوارزمية MNA مكتوبة يدوياً (بدون مكتبة خارجية) | تحكّم كامل بالدقة والأداء على هواتف متوسطة |
| التخزين المحلي | `shared_preferences` + ملفات JSON عبر `path_provider` | بسيط، موثوق، بدون حاجة لقاعدة بيانات كاملة |
| الملفات/المشاركة | `file_picker`, `share_plus` | استيراد/تصدير/مشاركة ملفات المشاريع |
| الأيقونة | `flutter_launcher_icons` | توليد أيقونات كل الدقة المطلوبة من صورة واحدة |
| CI/CD | GitHub Actions (`subosito/flutter-action`) | بناء APK فعلي دون الحاجة لأي أدوات محلية |
